# Product Description Enhancer

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/b2dcbd47ed/badge.svg)](https://ask.thili.ai/b/b2dcbd47ed)

A local Streamlit app that fine-tunes **DistilGPT-2** with an explicit, custom PyTorch LoRA implementation. It generates product copy from user supplied facts; it does not call a paid API. If the language model output cannot be checked against the exact product name and specifications, the app shows a separate, visibly labeled specification-only fallback and keeps the raw model output available for review.

## Features

- 100 synthetic product/specification/description examples across electronics, fashion, home and kitchen, fitness, and stationery.
- JSONL validation, cleanup, duplicate detection, deterministic train/validation split, completion-only causal LM labels, truncation, and dynamic padding.
- DistilGPT-2 fine-tuning with custom low-rank adapters and frozen base weights.
- Streamlit inputs for product name, category, specifications, and tone, plus copy/select and download.
- Adapter loading, standalone merging, and base versus adapted output evaluation.
- A conservative inference gate that requires the exact product name and every supplied specification value, rejects unsupported numbers and ungrounded content words, and otherwise uses an explicit factual fallback. The adapter output and final display text are stored separately.
- CPU support by default, with CUDA used when PyTorch reports it available.

## Architecture

```text
data/products.jsonl ──> app/dataset.py ──> tokenizer ──> app/training.py
                                                        │
                                      frozen DistilGPT-2 + LoRALinear(c_attn)
                                                        │
                                      adapter.pt + adapter_config.json + tokenizer
                                                        │
Streamlit ──> exact training prompt ──> app/inference.py ──> grounding gate ──> display
                                                              └─> spec-only fallback
```

`LoRALinear` wraps the GPT-2 `c_attn` attention projection (a Hugging Face `Conv1D` weight layout). It trains rank-8 A/B matrices with alpha 16 by default; A uses Kaiming initialization, B starts at zero, and the original model parameters remain frozen. The trained adapter in this workspace contains 147,456 trainable parameters out of 82,060,032 (0.180%). The adapter is loaded on top of the matching pretrained base model; it is not a replacement language model.

The inference prompt comes from the same `format_example()` function used by training preprocessing. Sampling is configurable; evaluation uses deterministic decoding. The output gate is intentionally strict: it favors specification fidelity over stylistic variation. It is a lexical safeguard, not a proof that every natural-language claim is true. A fallback contains only the submitted product name, category, spec labels, and values, and the UI identifies it as fallback text rather than model output.

## Data

The 100 examples are synthetic and deterministically generated by `python -m app.generate_synthetic_dataset`. They are demonstration data, not retailer copy or verified product facts. The templates are repetitive and small; they are not sufficient evidence of production-quality marketing. Review all input facts and generated content before publishing.

## Requirements and hardware

Python 3.10–3.12 is recommended. The default base model is `distilgpt2`, a compact model downloaded by Transformers on first use. Training and inference use CPU when CUDA is unavailable. An AMD integrated Radeon GPU is not assumed to have a supported PyTorch backend, so CPU operation may be slow. Defaults use batch size 1, sequence length 384, rank 8, and three epochs. No API key is required.

## Setup and training (Windows PowerShell)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python -m app.generate_synthetic_dataset
python -m app.training
```

Adjust `BASE_MODEL`, `MODEL_DIR`, `SEED`, `LORA_RANK`, `LORA_ALPHA`, `LORA_DROPOUT`, `EPOCHS`, `BATCH_SIZE`, `LEARNING_RATE`, `MAX_LENGTH`, and `VALIDATION_FRACTION` in `.env`. Environment variables can also be set directly. The base checkpoint is downloaded by Hugging Face; it is not stored in this repository.

Training writes `adapter.pt`, `adapter_config.json`, and a tokenizer folder under `MODEL_DIR`. It logs training and validation loss per epoch. It does not overwrite or delete the trained adapter when you launch the UI.

## Launch the app

```powershell
streamlit run app/main.py
```

If adapter weights or tokenizer files are missing, generation is disabled and the page explains that the model needs to be trained/restored. Generation errors are shown in the app. When fallback is used, the page labels it and provides an expander for the raw LoRA output.

## Evaluate and merge

```powershell
python -m app.evaluation --sample-size 10
python -m app.inference --merge
```

The evaluation report contains raw base and fine-tuned outputs, the final grounded text, fallback decisions, literal specification-value coverage, and blank human-review fields. Coverage is a lexical overlap metric; it is **not** factual accuracy, relevance, fluency, or human quality. Human ratings stay blank until a person reviews the examples. The merge command saves a standalone model under `MODEL_DIR/merged`.

### Existing local run (not a quality claim)

The local adapter metadata records three CPU epochs over 85 training and 15 validation rows. Training loss went from 2.5962 to 0.9393; validation loss went from 1.5619 to 0.6813. Falling loss alone does not show that generated copy is good or factually reliable.

The actual evaluation report currently compares 10 held-out examples. Mean literal spec-value coverage was **0.067** for the base model and **0.100** for raw fine-tuned output. The grounding gate used the fallback on **10/10** fine-tuned examples; the final fallback text had **1.000** lexical spec coverage by construction. That 1.000 is not a model score. No human quality or factual-accuracy ratings have been collected. See `artifacts/distilgpt2-lora/evaluation_report.json` locally; artifacts are excluded from Git.

## Tests

```powershell
python -m pytest -q
```

Tests cover malformed and duplicate data, prompt construction, preprocessing and splits, adapter injection/freezing/state loading, forward and merged equivalence, grounded fallback behavior, missing model files, and actual inference with the local trained adapter when its base checkpoint is cached. The adapter integration test explains when it cannot run because local model artifacts are absent.
